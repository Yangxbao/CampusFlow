## 附二、最容易被追问的 5 个"第二层问题"（提前备好）

1. 答"Lua 原子"之后必被问"**Lua 本身执行时间多长？会不会成瓶颈？**"
   → 单脚本 HGET×3+INCR+GET/DECR+SADD+SET，微秒级；Redis 单线程 10 万 QPS
   才是上限，压测 2000/s 远未到（进一步优化：分桶，16 讲练习 8）；
2. 答"本地消息表"之后必被问"**表会不会越来越大？**" → CONFIRMED 记录可归档
   （保留 N 天），扫描只查 NEW/FAILED——需要 (status,next_retry_time) 类索引支持；
3. 答"Redisson 看门狗"之后必被问"**Redisson 挂了锁怎么办？**" → 锁随客户端失联
   最终过期；业务幂等兜底；主从切换场景见 14 讲 Q18；
4. 答"user_id 分片"之后必被问"**user_id 大户怎么办？**" → 校园场景单用户报名数
   有业务上限（一学期几十场），天然倾斜有限；极端场景用 user_id+gene 混合分片；
5. 答"P99=5ms"之后必被问"**JMeter 在同一台机器上，数字可信吗？**" → 如实回答
   局限（同机资源竞争），补充 IT 竞态验证与四断言才是正确性证据——**诚实处理
   数字边界比辩护数字本身更专业**。
